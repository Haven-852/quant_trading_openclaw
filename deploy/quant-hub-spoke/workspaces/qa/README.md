# 测试沙盒（QA）

- **OpenClaw agent id**：`quant-qa`
- **Docker**：`quant-qa`

## 职责定位与启用条件

**QA 在本流程中的主战场是：程序已具备「可执行回测」能力之后。**

- **在此之前**（尚无稳定回测入口、数据管线未通、策略骨架未成型）：以 Engineering 自测与单元测试为主，**不强制**占用 QA 沙盒做大规模验收。
- **进入 QA 的典型门槛**（由 Seth 在任务书中勾选）：  
  - 回测脚本或 CLI/服务可在 **`E:\demo\backtrader`** 内 **非交互、可重复** 跑通；  
  - 策略/模型与数据路径已在工程侧 **按约定版本固定**。

## 工作内容

1. **按正确策略模型执行**：严格依据 Engineering（及研究员需求中）定义的 **策略规格**（信号逻辑、仓位、成本、滑点、复权与频率等）执行回测与回归，**不擅自改模型语义**；发现与规格不符时 **报缺陷** 而非在 QA 侧「改策略凑结果」。
2. **回测为主**：组织短/长样本回测、边界与压力场景；记录 **命令、参数、数据区间、日志与关键指标** 到 `REPORT.md`（或 Hub 指定路径）。
3. **连通与正确性**：在 `E:\demo\backtrader\tests` 中与回测相关的用例、以及与前后端展示链路相关的用例，按工程规范补跑并归档结果（与 `../engineering/README.md` 中的测试约定一致）。

## 与 Research / Engineering 的边界

- **Research**：提供需求与依据，**不**替代 QA 做回测执行结论。
- **Engineering**：交付可回测的实现；QA **验证是否按规格运转**，不负责重写策略逻辑（除非任务明确授权修复缺陷）。
