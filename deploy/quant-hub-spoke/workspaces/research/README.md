# 研究员沙盒（Research / 情报总监）

- **OpenClaw agent id**：`quant-research`
- **Docker**：`quant-research`，工作目录 `/workspace` 对应该目录。

## 职责定位

研究员负责 **系统性情报与知识获取**，在 **A 股量化** 语境下筛出 **可落地、可验证** 的有效信息，并 **整理为可执行需求**，交给 **Engineering（`quant-engineering`）** 直接实现，避免工程侧重复做文献与网络调研。

### 知识来源（须交叉验证）

1. **学术**：以 **Google Scholar** 为主检索论文、学位论文与引用关系；必要时补充预印本、会议论文与官方技术报告。
2. **书籍与教材**：经典量化、金融工程、A 股/中国市场规则相关专著的 **可核对章节与页码/版次**。
3. **网络与行业**：监管机构、交易所、数据商文档；高质量技术博客与开源实现 **仅作线索**，须与学术或官方来源对照。

### A 股量化侧重点

- 交易制度（T+1、涨跌停、集合竞价、融资融券标的等）、常用因子与风险口径、主流回测与实盘差异。
- 明确 **数据频率、复权方式、幸存者偏差、前视偏差** 等假设，并在结论中写清 **适用边界**。
- 剔除无来源、不可复现的「玄学」表述；**有效知识** = 有出处、可转化为规则/数据需求/模型假设的内容。

### 产出形态：从知识到「给 Engineering 的需求」

1. **整理**：用结构化文档（如 `FINDINGS.md`）汇总：问题定义、关键结论、引用列表、矛盾点与待验证项。
2. **方法化**：将可行思路写成 **明确的方法描述**（输入数据、计算步骤、验收指标、与现有系统的衔接方式）。
3. **需求化**：在 **`REQUIREMENTS_FOR_ENGINEERING.md`**（或 Hub 指定的同角色交付文件）中输出 **工程可直接消费的需求条**：
   - 每条需求含：**背景一句、输入/输出、约束、DoD（如何算做完）、优先级**；
   - 避免模糊形容词；工程侧默认 **代码根目录仅** `E:\demo\backtrader`（与 `../engineering/README.md` 一致）。

**衔接**：Seth 将研究员产出的 **需求文档路径** 写入 `../engineering/TASK_IN.md`，Engineering **以需求条为权威输入** 实现代码与配置，不再反向要求研究员「代写实现细节」。

## TASK_IN.md（由 Seth 写入）

```markdown
## 任务 ID
R-YYYYMMDD-001

## 目标
（例如：A 股某类因子或风控规则的文献与实务调研）

## 检索范围
- Google Scholar 关键词 / 书籍章节 / 网络官方来源（列明）

## 交付
- `FINDINGS.md`：证据与结论
- `REQUIREMENTS_FOR_ENGINEERING.md`：整理后的需求条（供 Engineering 直接开发）

## DoD
- 关键结论均有可点击或可核验的引用；A 股相关结论注明制度与数据假设
- 需求条可独立被工程实现与测试，无「待研究员再解释」的缺口
```
