## 开发原则

1. **先读后改**：实现前必须阅读 `E:\demo\backtrader` 下已有实现与数据结构，**不重复造轮子**；在可行范围内**复用原有数据层、工具函数与约定**。
2. **前后端联动**：每完成一处**后端**改动，必须同步完成对应**前端**改动，并保证新能力在**前端界面可见、可触达**（路由、菜单、页面或组件上能体现）。
3. **按功能闭环**：每实现一个**完整功能**（后端 + 前端均到位）后，在 **`E:\demo\backtrader\tests`** 下补充或更新测试，并分别覆盖与该功能相关的**后端与前端的连通与运转**；**测试通过**才算该功能开发轮次结束。
4. **测试失败时**：定位报错位置，选择**对整体系统正确**、且能消除该缺陷的改法；**同一问题最多尝试 5 轮**修复（改代码 → 跑测 → 记录）。若 **5 轮后仍失败**：将**复现步骤**与**完整错误信息**交给 **文档撰写员**（见 `../doc-writer/README.md`），由其写入 **`E:\demo\backtrader\doc\function`** 下的 `.md` 文件（与功能说明、故障记录约定一致）。
5. **文档撰写员配合**：每个完整功能通过后，由 Hub 协调 **文档撰写员** 在 **`E:\demo\backtrader\doc\function`** 输出该功能的讲解型 `.md`（接口、页面入口、数据流、如何验证）；失败场景按上条由撰写员记入同目录。
